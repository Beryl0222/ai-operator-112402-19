# 离线长文排版的参数化单调输运与联动书签

这里的长稿稀疏排版页是用于设备联调的合成资料。使用 Node.js 22。运行 `npm ci --offline` 核对依赖锁，`npm run inspect` 查看资料字段，`npm test` 检查资料格式及相互引用。检视脚本只读取元数据。

## 数据格式

源词按 ordinal 排序，拥有正整数质量 q；每个目标格有整数上限 cap。分配为非负整数，未出运按每单位 skip 付费。任意两条正流 i→j、k→l，如 i<k 则 j≤l。相同 ordinal 的跨视图引用是同源。每条边只在自己的 section 可用，跨区例外以 bridge 给出的边为准。成本 a+b*t，其中同一个参数 t 是本卷共享闭区间中的实数，有理断点按精确符号处理，加载后参数可以收窄为点。打开及后续页是候选的全集描述，尚未送达的补页不会引入描述外的边。合法锚以 [word,slot,min] 给出，必须满足；冲突定位为包含发生矛盾的锚的区段范围，列明涉及的锚。书签的每端必须在所有最优流中把其指定的源质量全部给同一个槽，两个端点及其区间内经过的桥还要在同一版有连续出版许可。updatePages 按调用者交付次数计，重复同一页也计。workBytes 包含尚未领的流和区段证据及私有临时工作区，不包含交付端保有的输入以及已领取结果。 公开出版边界只限制迁移与历史解释，不删除成本图中仍然存在的桥。book 的实际联合落点一并看两端和中间可用桥，每个引用的发布范围以开版稿段的单调字序为准。

## 取数

`inputs/layout-pages.json` 保存标定、规格和调用记录。记录中的范围除明确说明外从零开始，使用半开区间。批量数组按调用记录列出的顺序交付。layoutPage(page) 读源词、目标、同页登记锚及候选边。目标页允许排在源页之后。

## 引擎实现（src/）

- `fraction.mjs`：BigInt 有理数。字宽参数 `t` 与所有有理断点精确表示，成本 `a+b*t` 按同分母整数比较，杜绝浮点符号误差。
- `transport.mjs`：单调（非交叉）整数输运求解器。源词按质量、目标槽按容量单元化，非交叉约束等价于序列对齐（跳过供应付 skip、跳过槽免费、匹配付边成本）。稀疏滚动行 DP 只保留可达漂移，主成本并列时以 `(shipped, 槽序和)` 次级目标取 max/min 两极；强制锚 `[word,slot,min]` 先做容量/顺序/边校验再切分子问题，矛盾返回带区段范围与涉及锚的结构化冲突，绝不静默跳过。
- `envelope.mjs`：参数化最优解包络。每个计划是直线 `A+B*t`，最优成本是线性函数的下包络；递归用精确有理交点枚举断点，收集区间内全部最优计划。`settleWord` 判定某词是否在所有仍可能字宽、所有最优流下都把整词质量送到同一槽。
- `model.mjs`：按需取页（每次交付计数，重复也计），按 section/bridge 切连通组件并单元化。无桥 section 各自独立，增量更新只重算受影响组件。
- `work-ledger.mjs`：workBytes 私有工作区记账。DP 按滚动窗口高水位计费（同时存活的滚动行），与组件总长度无关；不含交付端输入与已领取结果。
- `engine.mjs`：主引擎。维护共享字宽闭区间与收窄点、锚、出版阻塞段、书签/别名与版本快照。计算状态（`settled`/`uncertain`）与出版状态（`publishable`/`blocked`）分别报告，不合并。书签两端在全最优解族下同槽、且两端与区间内桥在同一版有连续出版许可才可迁移；批准时冻结整段版本，回读与历史解释永远返回审批时坐标，后续改稿不改写旧划线。
- `replay.mjs` / `run.mjs`：按 `events` 记录重放联调流程并输出事件轨迹与交付/工作区对账。

### 运行

- `npm run replay`：重放事件记录，输出每步双状态、锚冲突定位与最终对账。
- `npm test`：28 个测试，含有理数、toy/随机模糊对照暴力枚举的最优性与流合法性、参数包络断点、锚冲突、双状态分离、快照冻结、别名同序、增量缓存与 workBytes/交付额度对账。
