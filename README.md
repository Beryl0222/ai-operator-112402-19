# 低内存文本换行的稀疏单调输运算子

项目资料使用可独立读写的 JSON。Node.js 22.23.4 下运行 `npm ci --offline` 准备环境，然后运行 `npm run inspect` 检查合成数据字段，运行 `npm test` 校验样本引用及格式。

## 输入契约

每个源/目标有整数容量。运输量为非负整数，源质量可拆，目标容量不可超。源点有 skip 单位费用；锚点给最少运输量。对于任何两条正流边 i→j、k→l，若 i<k 则 j≤l，同一源可拆到多个目标，若同源的实际拆法使光标不能得出唯一目标，保持未确定。候选边费用和锚位在一修订内有效；未加载的折叠区域给候选位置和成本区间，其他资料相同。工作区计内部候选、最优性证据和暂未领取落点。

## 资料读取

样本位于 `inputs/session.json`，其中 `events` 是按到达顺序记下的操作，编号从零开始。open/edit 给出排版修订；check/migrate 查询源词 ID；unfold 提交源、目标下标及真实费用；anchor 设定边与最少量。

## 设备联调资料

长稿使用 `inputs/qualification.json` 定义页面，`qualification.mjs` 按页物化旧词、目标、候选和锚。源、目标 ID 在全部页中全局唯一。源质量未移至任何真实目标的余额按 skip 计费。禁止外运的区域由输入的 sources 和 targets 的 `section` 相同决定，页号只用于取数。代价区间为可独立补全的闭的整数区间。流量仅按成本最小化。评分若要返回一个展示用最优流，可以选择任何最优解，不能用该选择提前确认唯一光标。已知实词存在但明确删除的来源可由输入 `deleted` 识别，折叠字段为区间的边只在 `unfold` 后变为确定成本。`anchor` 为指定边添加最少量，超过目标剩余容量仍不可跳过。`views` 中多处索引同一 `word` 时共享该词的一份质量。
源公开页大小 `rowsPerPage`。长稿联调查阅 `events`，折叠区相关查询自 `unfold` 起到下一次 `read` 的源页读取次数上限为 `updateReads`。同页重复读取计次数。边界在完成公开区段的首次输入时按其稿件 `section` 判定，不能根据页号判定。工作区 `maxWorkBytes` 包含尚未领取的流、候选状态内存、正确性证据与运行临时内存，不含供应方已持有的输入字节或调用方持有的结果。
